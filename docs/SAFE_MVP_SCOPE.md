# SAFE_MVP_NO_RUNNER: bounded API scope

RPF-012S is a backend-only, runner-free stepping stone, not the run lifecycle in RPF-012A. It depends on the completed backend v1 contract foundation RPF-001C-BE. It must preserve the existing health, authentication and security behavior. No frontend commit is implied. UI adoption requires a separately scoped frontend ticket.

## Acceptance criteria for RPF-012S

- Require an authenticated session for both endpoints, with explicit fixture access checks. Preserve the existing origin, CSRF, cookie and CORS protections. Return contract-conforming 401/403 or concealed 404 for unauthorized access; never expose session, token, private filesystem, artifact or runner details.
- `GET /api/v1/repositories` returns a strictly validated catalog of approved fixture metadata from a server-owned allowlist. Include only explicitly public identifiers and labels. The existing `fixtures/discount-bug/manifest.json` is available as curated metadata; its test files and scripts must not be executed. Any snapshot must be labeled curated, not a live GitHub fetch. Do not expose the full manifest, command lines, local paths, reference patch, or sensitive configuration. Reject or fail closed on malformed or unapproved fixture data.
- `POST /api/v1/runs` validates the existing backend-owned create-run contract, authentication and fixture authorization. In SAFE_MVP_NO_RUNNER mode, an otherwise valid authorized request returns HTTP 503 with the v1 error envelope code `RUNNER_UNAVAILABLE`. Invalid input, absent authentication and unauthorized fixtures fail appropriately before acceptance. The response is an operational error, not a verdict.
- The fail-closed path creates no run, snapshot, approval, job, event or report; queues no work; invokes no model or runner; executes no fixture; and performs no GitHub write. Do not return `VERIFIED`, `REJECTED`, `NO_REPRO`, `INCONCLUSIVE`, a fake run ID, or a success state. Do not infer runner availability from Docker or a VM alone.
- Test HTTP behavior with trusted test-only fixtures: approved and unapproved catalog entries; unauthenticated and unauthorized requests; valid and malformed run requests; strict error envelope and request IDs; CORS and CSRF regressions; no persistence, queue, execution or external calls on the unavailable path. Use disposable test resources. Run existing tests, lint, typecheck, build and diff checks. Tests using mocks establish API behavior only, not isolated execution or live GitHub evidence.

RPF-012A retains real run lifecycle, ownership, idempotency and approval acceptance after RPF-011B and the backend contract. RPF-012B retains real events, reports and artifact authorization. RPF-001C remains incomplete until live frontend/backend integration proves its full acceptance. RPF-009, RPF-010B and RPF-011B retain their existing runner-evidence dependencies. RPF-004 remains IN_PROGRESS and RPF-006A remains suspended. A future production runner must independently satisfy isolation, frozen-byte integrity, authenticated provenance and deterministic policy before any execution verdict.
